# 2. GROUP BY + HAVING

## Core Understanding

### GROUP BY

Creates groups.

Example:

* group employees by department
* group customers by city
* group orders by customer

### HAVING

Filters groups AFTER grouping.

Example:

* departments having salary > 1 lakh
* duplicate customer IDs

## Important Difference

| Clause | Works On |
| ------ | -------- |
| WHERE  | rows     |
| HAVING | groups   |

## Practice Scenarios

* duplicate detection
* customer count per city
* order count per customer
* region-wise sales

## Sample Pattern

```sql
SELECT customer_id, COUNT(*)
FROM orders
GROUP BY customer_id
HAVING COUNT(*) > 1;
```

# 4. NULL VALIDATION

## Important Rule

WRONG:

```sql
WHERE customer_id = NULL
```

CORRECT:

```sql
WHERE customer_id IS NULL
```

## NULL Count Validation Pattern

```sql
SELECT
COUNT(CASE WHEN customer_id IS NULL THEN 1 END) AS customer_id_nulls
FROM customer_table;
```

## Real ETL Use Cases

* bad ingestion
* missing join keys
* schema quality checks
* pipeline validation

## Important Understanding

CASE WHEN creates conditional logic.
COUNT counts non-null values.

# 6. ROW_NUMBER()

## Purpose

Assign unique numbering inside groups.

## Important Pattern

```sql
ROW_NUMBER() OVER (
PARTITION BY customer_id
ORDER BY update_time DESC
)
```

## Important Understanding

### PARTITION BY

Creates invisible groups.
Rows stay alive.

### ORDER BY DESC

Newest/largest value first.

### ROW_NUMBER

Assigns numbering inside group.

## Real ETL Use Cases

* latest record extraction
* deduplication
* CDC cleanup
* incremental processing

---

# 7. RANK() vs DENSE_RANK()

## Difference

| Function   | Duplicate Values  | Gap Exists? |
| ---------- | ----------------- | ----------- |
| ROW_NUMBER | different numbers | no          |
| RANK       | same rank         | yes         |
| DENSE_RANK | same rank         | no          |

## Important Understanding

### RANK

Counts positions.
Can skip numbers.

### DENSE_RANK

No gaps.
Continuous ranking.

# 8. LATEST RECORD VALIDATION

## Real Scenario

Multiple customer updates exist.
Need latest row only.

## Important Pattern

```sql
SELECT *
FROM (
    SELECT
        customer_id,
        city,
        update_time,
        ROW_NUMBER() OVER (
            PARTITION BY customer_id
            ORDER BY update_time DESC
        ) AS rn
    FROM customer_updates
) t
WHERE rn = 1;
```

## Important Understanding

Need ordering logic:

* timestamp
* version
* sequence ID
* effective date

Without ordering logic:
latest record cannot be determined.

# 9. INNER JOIN

## Rule

Keep ONLY matching rows.

## Important Understanding

INNER JOIN behaves like intersection.

## Common Problems

* row loss
* duplicates
* join explosion

## Example

```sql

FROM customers c
INNER JOIN orders o
ON c.customer_id = o.customer_id;
```

## Real ETL Issues

* missing records

* reconciliation failures

# 10. LEFT JOIN

## Rule

Keep ALL rows from LEFT table.

If match missing:
RIGHT table columns become NULL.

## Important Pattern

```sql
SELECT *
FROM customers c
LEFT JOIN orders o
ON c.customer_id = o.customer_id;
```

## Important Understanding

LEFT JOIN heavily used for:

* missing record validation
* reconciliation
* orphan detection
* incremental loads

# 15. AGGREGATE VALIDATION

## Goal

Validate business totals.

## Important Understanding

Counts may match but totals may differ.

## Important Functions

* SUM()
* AVG()
* MAX()
* MIN()

## Region-wise Aggregate Comparison Pattern

```sql
SELECT
s.region,
s.source_total,
t.target_total
FROM
(
    SELECT region, SUM(sales_amount) AS source_total
    FROM sales_source
    GROUP BY region
) s
JOIN
(
    SELECT region, SUM(sales_amount) AS target_total
    FROM sales_target
    GROUP BY region
) t
ON s.region = t.region
WHERE s.source_total != t.target_total;
```

## Important Learning

Aggregate BEFORE joining.
Avoid join explosion.

# 16. JOIN EXPLOSION

## Important Understanding

Joining raw transactional rows can multiply records.

Example:

* Mumbai exists twice in source
* Mumbai exists twice in target

Join creates:

* 2 x 2 = 4 combinations

## Solution

Aggregate first.
Then compare summarized data.

Very important ETL concept.

# CASE WHEN & CONDITIONAL AGGREGATION

# 1. WHAT IS CASE WHEN?

CASE WHEN is SQL's IF-ELSE logic.

It is used to:

* categorize data
* transform values
* create validation flags
* generate business rules

---

## Basic Syntax

```sql
SELECT
customer_id,
CASE
    WHEN salary > 100000 THEN 'HIGH'
    ELSE 'NORMAL'
END AS salary_category
FROM employee_salary;
```

---

## Easy Memory

WHERE answers:

```text
Which rows should I keep?
```

CASE WHEN answers:

```text
How should I label or transform this row?
```

---

# 2. CASE WHEN EXAMPLE

Input:

| emp_name | salary |
| -------- | ------ |
| Rahul    | 120000 |
| Amit     | 75000  |
| Neha     | 40000  |

Query:

```sql
SELECT
emp_name,
salary,
CASE
    WHEN salary > 100000 THEN 'HIGH'
    WHEN salary BETWEEN 50000 AND 100000 THEN 'MEDIUM'
    ELSE 'LOW'
END AS salary_category
FROM employee_salary;
```

Output:

| emp_name | salary | salary_category |
| -------- | ------ | --------------- |
| Rahul    | 120000 | HIGH            |
| Amit     | 75000  | MEDIUM          |
| Neha     | 40000  | LOW             |

```sql
    END
)
```

* validation reports

---

# 5. NULL COUNT VALIDATION

Table:

| customer_id |
| ----------- |
| 101         |
| NULL        |
| 103         |
| NULL        |

Query:

```sql
SELECT
SUM(
    CASE
        WHEN customer_id IS NULL THEN 1
        ELSE 0
    END
) AS null_customer_id_count
FROM customer_validation;
```

Output:

```text
2
```

---

# 6. MULTIPLE VALIDATIONS IN ONE QUERY

```sql
SELECT
SUM(
    CASE
        WHEN customer_id IS NULL THEN 1
        ELSE 0
    END
) AS null_customer_id_count,

SUM(
    CASE
        WHEN city IS NULL THEN 1
        ELSE 0
    END
) AS null_city_count
FROM customer_validation;
```

Output:

| null_customer_id_count | null_city_count |
| ---------------------- | --------------- |
| 2                      | 2               |

---

# 7. SUCCESS / FAILURE COUNT

Input:

| status  |
| ------- |
| SUCCESS |
| FAILED  |
| SUCCESS |
| FAILED  |

Query:

```sql
SELECT

SUM(
    CASE
        WHEN status = 'SUCCESS'
        THEN 1
        ELSE 0
    END
) AS success_count,

SUM(
    CASE
        WHEN status = 'FAILED'
        THEN 1
        ELSE 0
    END
) AS failed_count

FROM batch_audit;
```

Output:

| success_count | failed_count |
| ------------- | ------------ |
| 2             | 2            |
